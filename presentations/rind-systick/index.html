How SysTick works

SysTick is a 24-bit counter that counts down to zero, reloads, and sets a flag each time it wraps

SysTick is required in ARMv7-M and optional in ARMv6-M. The RP2040 (ARMv6-M) and the EFR32MG24 (Armv8-M) both include it. On the RP2040 the other clock choice is a 1 µs tick from the watchdog block.

Wrap time

At 125 MHz SysTick wraps every 134 ms, so one raw reading can only time short operations

Time until each counter wraps (log scale)

The arithmetic

  • Wrap time = 2bits ÷ clock. Resolution = 1 ÷ clock.
  • SysTick counts down, so elapsed = (start − end) mod 224. That is only right if less than one wrap passed.
  • An up-counter (CYCCNT, CCOUNT) gives elapsed = end − start in unsigned 32-bit arithmetic, with the same one-wrap limit.

Bits and clocks come from the sources in the footer. Values marked "computed" are this arithmetic, not measurements. The RP2040 figures match hosts/rp2040/NOTES.md.

Going past 24 bits

Counting wraps in software stretches SysTick to 32 or 64 bits, which is what the RP2040 images do

The RP2040 images run SysTick at the processor clock (1 count = 1 cycle) and extend it in software to 32 bits (wraps every 34.4 s at 125 MHz). The first Pico run showed a COUNTFLAG double-count: the handler never read SYST_CSR, so the next cycles() call added a second 224 cycles (134 ms) whenever a sample crossed a wrap. The handler now reads CSR. The 1 MHz TIMER cross-check lasts 300 ms, at least two wraps: 37,500,815 cycles against 300,021 µs (125.0 MHz). (rind-hardware a9d057a; wrap time from NOTES.md at 2cb88c3)
Recommendation: one way to extend it
  1. Set RELOAD = 0xFFFFFF, CLKSOURCE = 1, TICKINT = 1, ENABLE = 1.
  2. The SysTick handler adds 1 to a wrap count hi.
  3. To read: take hi, then CVR, then hi again. If hi changed, read again.
  4. Time = hi × 224 + (0xFFFFFF − CVR). A 64-bit hi gives a 64-bit count.

Things to watch

  • Reading SYST_CSR clears COUNTFLAG. Code that polls COUNTFLAG and an interrupt handler that relies on it will steal the flag from each other; pick one. That is what happened on the first Pico run, before the handler was changed to read CSR.
  • Writing SYST_CVR clears the count and COUNTFLAG. Do not write it while timing.
  • The wrap interrupt runs inside timed regions. Its cost lands in the samples; long samples make it a small share.
  • When a wrap lands while cycles() has interrupts masked, the harness counts it, clears the pending SysTick (ICSR.PENDSTCLR), and re-reads CVR so the handler does not count it again. (rind-hardware a9d057a)

Pitfalls

Torn reads, interrupts, flash stalls and clock changes can each spoil a timing without any error

Torn reads

  • A 64-bit value read as two 32-bit halves can mix two moments. The RP2040's TIMELR read latches TIMEHR, which breaks when two cores read it; the datasheet's SDK code reads TIMERAWH, TIMERAWL, TIMERAWH and repeats if the high half changed.
  • On aarch64, reads of CNTVCT_EL0 can be speculative and out of order; Arm's examples put an ISB before the read.

Interrupts

  • Any handler that runs inside a timed region adds its whole cost to that sample, including SysTick's own wrap interrupt when TICKINT = 1.
  • The median of several samples keeps a rare interrupt from setting the result.

Flash stalls

  • RP2040 code runs from external flash through a 16 kB, two-way cache with 1-cycle hits; a miss waits on the QSPI flash.
  • On the ESP32-S3, instruction-cache misses with ESP-IDF's default 16 KB cache explain several published gaps (SHA-256, HMAC, HKDF, XChaCha20-Poly1305).

Clock changes

  • The Pi 5 in these results is capped at 1.5 GHz (rated 2.4 GHz, governor ondemand), so its times are 1.5 GHz times.
  • The generic timer runs at a fixed frequency, not the CPU clock, so its ticks are wall time, not cycles.
  • The EFR32MG24 starts on a 20 MHz oscillator after reset.

Per chip: microcontrollers

The M0+ has only SysTick and a 1 µs timer, while the M33, M4 and Xtensa chips also have a 32-bit cycle counter

Per chip: application processors

The Pi 5, M1 and Pixel use the Arm generic timer instead of SysTick, and it counts wall time at a fixed rate

  • The published Pi 5, M1 Pro, Pixel 9 Pro and Xeon VM runs used criterion, which times with Rust's Instant: clock_gettime(CLOCK_MONOTONIC) on Linux and Android, CLOCK_UPTIME_RAW on macOS.
  • SysTick is defined in the M-profile architecture manuals; A-profile cores like these use the generic timer.
  • Armv8.6 and later fix the generic timer at 1 GHz; earlier cores use a fixed rate, typically 1 to 50 MHz, given in CNTFRQ_EL0.

Reading each counter

Each counter has one safe way to read it, and the 64-bit ones need a retry or a barrier

SysTick (RP2040, MG24)

// counts down; 24 bits
uint32_t a = SYST_CVR;
work();
uint32_t b = SYST_CVR;
cycles = (a - b) & 0xFFFFFF;  // < 1 wrap

RP2040 TIMER, 1 µs, 64 bits

hi = TIMERAWH;
do {
  lo = TIMERAWL;
  hi2 = TIMERAWH;
  if (hi == hi2) break;
  hi = hi2;
} while (1);
us = ((uint64_t)hi << 32) | lo;

DWT CYCCNT (M33, M4)

DEMCR |= TRCENA;          // bit 24
// check DWT_CTRL.NOCYCCNT == 0
DWT_CYCCNT = 0;
DWT_CTRL |= CYCCNTENA;    // bit 0
a = DWT_CYCCNT; work(); b = DWT_CYCCNT;
cycles = b - a;           // u32, < 1 wrap

aarch64 generic timer

isb
mrs x0, cntvct_el0     // start
...
isb
mrs x1, cntvct_el0     // end
mrs x2, cntfrq_el0     // ticks per second
ns = (x1 - x0) * 1e9 / x2
