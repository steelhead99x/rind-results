What it shows · causes measured with a component probe on the device

Three gaps, each with a measured cause

ChaCha20-Poly1305 16 KB
  • Same ChaCha20 assembly as OpenSSL: 5.04 against 5.05 cycles per byte.
  • Poly1305: BoringSSL's NEON code at 2.75 cpb against OpenSSL's at 1.69 cpb.
  • That explains about 9.1 µs of the 10.1 µs gap.
Small messages
  • 32 B costs 0.29 to 0.33 µs more per call than aws-lc-rs and OpenSSL.
  • The cipher drops to the integer path under 192 B: 191 B takes 1370 ns, 192 B takes 797 ns.
  • QUIC ChaCha20 header protection: 606 ns generic rounds, 437 ns in assembly.
P-256
  • rind ran Rust 32-bit Montgomery multiplication.
  • OpenSSL runs ecp_nistz256-armv4, which uses the prime's special form.
  • Field multiplication dominates a scalar multiplication, so the gap is there.
AES-GCM components add up: AES-CTR 14.2 µs plus GHASH 9.8 µs is 24.0 µs against the 24.83 µs seal. The open row includes a 7.48 µs 16 KB copy made by the bench.
