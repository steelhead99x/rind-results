14 November · steelhead99x/rind#82 · head ece9afa7

This board keeps the wide schedules. #82 is not measured on the Jetson

Linux selects the narrow (non-_alt) schedules only when every online core is Cortex-A72, Cortex-A76, or Neoverse N1. Cortex-A78AE is not in that list. An unrecognised part keeps _alt, the code this board already runs.

Measured, on a Pi 5, not here

Cortex-A76, 1.5 GHz cap, median of 5. X25519 252.8 → 107.7 µs (0.426×). RSA-2048 sign 5209.2 → 3071.6 µs (0.590×). P-256 keygen 52.1 → 36.6 µs (0.703×). Those commits do not change which schedule an A76 selects, and the table was not re-measured on ece9afa7. The full table is on the aarch64 deck.

Not measured

  • Jetson Orin Nano: not measured yet.
  • Cortex-A72 and Neoverse N1: selected by the same rule, not measured yet.
  • Forcing narrow on an M1 Pro is slower on every public-key row. The PR does not print those per-op times. Default detection keeps _alt.

14 November · steelhead99x/rind#79 · head 54d339e7

The P-256 table alignment applies on this aarch64 core. It is not measured here

  • The non-x86_64 generator table is #[repr(C, align(64))] AlignedTable. The array is 88,064 bytes, with no trailing padding. Placement padding is less than 64 bytes. Jetson is non-x86_64, so the layout applies.
  • The measured 2.5–3% effect was 16-byte loads of 64-byte points on a Cortex-A76. No speedup was measured on arm or portable.
  • The original Pi 5 timings were not rerun for the accessor refactor or this merge. Head 54d339e7 has no new Pi 5 number, and no Jetson number.
  • The published Jetson p256-ecdsa-sign time, 26.38 µs, is rind 98568332. It is not an A/B of this alignment.
#76 changes portable mul_add only. aarch64 Montgomery stays on assembly, so this board's RSA path is outside that pull. The portable result is an unnamed host, within about 1%, and is not a Jetson measurement.
