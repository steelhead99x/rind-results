# rind on Fire TV Stick (AFTSSS)

Local only; nothing pushed. 2026-11-19 (America/Los_Angeles) 09:38-10:12.

- Device: Amazon Fire TV Stick AFTSSS ("sheldonp"), MediaTek MT8695, 4x Cortex-A53 r0p4 (part 0xd03) at 1.69 GHz (interactive governor, 1.69 GHz in every snapshot), Fire OS 7.7.0.4 / Android 9 (API 28), kernel 4.4.162+ armv7l (32-bit userland), ~900 MB RAM (50-110 MB free, swap in use), security patch 2025-06-01.
- rind: steelhead99x/rind ac0f2f936cb25ab2f737fca1adde5923f64fa60a (same commit as the Galaxy A16 run), clean clone on the build host.
- Build: `cargo +1.98.1 bench -p rind-bench --features __bench_openssl,openssl-sys/vendored --target armv7-linux-androideabi --bench <16 benches> --no-run`; NDK r28c, `armv7a-linux-androideabi28-clang`, rustc 1.98.1. Built clean first try (about 6 min). No build issues.
- Run: single-threaded, pinned to CPU3 (toybox `taskset 8`), `--noplot --warm-up-time 1 --measurement-time 3`, filtered to rind, aws-lc-rs, ring, openssl on the main ops. 14 benches, 164 results, 118 rind-vs-other pairs: 88 faster, 17 even, 13 slower (5% band).
- Not run: rustls handshakes, RSA, P-521, HPKE, OPRF, VRF, SPAKE2+, Argon2, blind RSA, MD5, SHA-1 (time and 900 MB RAM). rustc/graviola/libcrux/dalek rows were skipped by the library filter (graviola does not build for 32-bit anyway).
- CPU path (see cpuid.json): AT_HWCAP=0x3fb0d6 (NEON), AT_HWCAP2=0x1f -> aes, pmull, sha1, sha2, crc32 all present *in AArch32 state* on this 32-bit userland. rind's arm backend (`rind_backend="arm"`, picked by build.rs from the `armv7` triple) detects the ARMv8 Crypto Extension through getauxval(AT_HWCAP2): `rind::cpu::has_aes_hardware()` = true. So AES, GHASH (PMULL), SHA-1 and SHA-256 run the aws-lc ARMv8-in-AArch32 assembly; SHA-512, ChaCha20, Poly1305, X25519 (BoringSSL NEON), Keccak-f (OpenSSL NEON) use NEON; P-256/P-384/Ed25519/ML-KEM/ML-DSA/HMAC/HKDF are portable Rust (libcrux, 32-bit limbs, `rind_limb="32"`); no SHA-3 instructions (not an ARMv8.2 core) and no DIT.
- Harness caveats: on-device run.sh was killed at ~09:47 PST (17:47Z) during `cipher` because the TV rebooted (uptime 29 min at 10:16 PST; boot reason reported as power_key/recovery); the process is not a low-memory kill as first guessed. aes_gcm, chacha20poly1305, xchacha20poly1305 are from that first pass; the other 11 binaries (cipher rerun from scratch) were driven from the host, one adb call per bench. Thermals were unreadable (thermal_zone*/temp permission denied for the shell uid); no battery; /proc/stat counters were non-monotonic, so no busy share. com.amazon.whad (Amazon audio service) burned ~1 core at the start, which could add a little noise.
