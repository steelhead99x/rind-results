# The Rust tools against the Python ones they replaced (2026-11-12)

The tooling of both repositories moved from Python and shell to Rust: here `cargo xtask`
(`tools/xtask`) and `cargo verify` (`tools/verify`, a separate crate sharing no code with
xtask), in rind-hardware `cargo xtask` (`xtask/`). Before the Python and shell versions were
removed, every artifact they produce was regenerated by both from the same inputs, at rind-results
`c1e96b2` (both versions present) with rind-hardware's rind submodule at `98568332`, and compared.

[`report-wording.diff`](report-wording.diff) is every difference between the Python and Rust
`RESULTS.md` and `RUNS.md`: the generator's name ("Generated by `cargo xtask report`"), the
gaps paragraph's name for the tool that refuses a missing entry, and the Reproduce block, which
now gives the Rust commands. Nothing else differs.

Not regenerated: the archived reports under `results/diag/` (the 40 MHz set and the diagnostics),
which `tools/report.py` wrote against older `admin/bench-report` tables; xtask refuses a table
snapshot that does not match the checkout, so they are kept as they were written. The scripts
under `scripts/` and `baremetal/` stay Python and shell: they drive rind's own Python renderer
and runner on the Mac, the Pi, the Pixel and the other boards, records of those one-off runs.

## How Python's output was matched

- JSON: Python's `json.dumps` layout (`indent=1`, `indent=2` for `runs.json`, one-line records
  with `", "` and `": "`), `ensure_ascii` escapes, and float `repr` (shortest digits, `1e-05`,
  `1.5e+16`); integers stay integers and floats keep `.0`, as Python's `json` round-trips them.
- `statistics.median` keeps the middle element itself for odd counts and averages for even.
- Formats: `:.Nf`, `:,.0f`, `:,` and rind's `human()`; the first of equal minima wins, as
  Python's `min`; dict insertion order is kept everywhere it shows.
- rind's tables (`SECTIONS`, `LIBRARIES`, `CRATES`, `SLOWER`) are built with comprehensions in a
  Python file, so `tools/bench-tables.json` holds them, evaluated by `cargo xtask bench-tables`
  and stamped with the file's sha256; every command checks the stamp against the checkout.
